# Gemini：网页授权后仍未登录

## 历史证据：仅配置验证，未完成登录验收
2026-11-20/21 Gemini Mac 1.147.5.1526：Failed to exchange auth code、curl 28；IPv4/IPv6 直连停在 SYN_SENT，而现有 Veee 代理访问 token 接口能收到响应。HTTP(S)_PROXY 启动法不足以覆盖这个 App 的登录流量。经用户授权安装 ProxyBridge 4.1.3 并启用系统扩展，Gemini 专用规则应用成功；记录结束时没有新一轮登录成功结果，不能叫已验证修复。

## 执行分支
1. 区分浏览器未授权、回调未交付、token 交换超时。先查目标 App 的相关日志、系统回调与已有登录状态；不要反复让用户点登录或找回密码。别采集授权 URL 的 code/state/token。
2. 确认当前代理端口、App 连接和必要目标连通性。无凭据探测即使返回 4xx，也仅证明传输层可达，不证明认证成功。不手工重放授权码。
3. 应用仍直连且环境变量未覆盖时，评估按应用转发。优先检查已有 ProxyBridge 版本、扩展状态、实际配置与启动方式；不重复安装或覆盖其他规则。安装/新增系统扩展需具体授权，下载须来自官方发布并核对签名/校验。历史允许安装不构成新机器上的授权。
4. 备份现有规则，只增加/调整目标 Gemini bundle 的 TCP 443 → 当前 SOCKS5 端点规则；本机 OAuth 回调应直连。历史端点是127.0.0.1:15235，必须现查；规则语法以已安装版 help/官方文档为准，不硬写旧 CLI 语法。不新增全局 * 规则。
5. 观察扩展已启用、规则加载与实际命中。系统授权按钮不一定触发跳转，先核对扩展真实状态。CLI 前台进程退出可能失效，不凭一条“applied”声称持久生效。
6. 用官方流程重新登录一次，观察目标账号与真实回复，再重启复测。失败保留脱敏证据并撤销本轮新增规则，恢复备份而不影响其他应用。成功后才将此分支本次结果标为已验证。
